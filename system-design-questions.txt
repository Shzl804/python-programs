===============================================

Profile: Intermediate learner
Use with: system-design-roadmap.md
Rule: Attempt each question before opening the linked material.
Score each answer from 0 to 4:
0 = cannot explain
1 = definition only
2 = definition plus example
3 = applies it in a design and explains trade-offs
4 = can design, implement, troubleshoot, and compare alternatives

READINESS CHECK
==============

Score each question from 0 to 4. A total of 300 or more is a strong intermediate result. Also complete at least eight timed designs. Every design should include:

- requirements and assumptions
- traffic, storage, and bandwidth estimates
- APIs
- data model
- high-level architecture
- database and cache choices
- consistency model
- scaling plan
- failure recovery
- security
- monitoring and alerting
- cost and trade-offs

Important: YouTube answer videos are learning references, not proof of mastery. If you cannot produce the design before watching the answer, repeat the problem after 48 hours without looking at the solution.
